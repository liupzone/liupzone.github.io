Agent（智能体）核心组件

内容来源：Awesome-AI-Pedia 知识整理

主流大模型 Agent 架构，一般分为基础核心组件 + 扩展能力组件，不同框架（LangGraph、AutoGen、OpenClaw 等）命名略有差异，但本质模块基本一致。

简化公式

Agent = LLM + 规划 + 记忆 + 工具

LLM 负责"想"，工具负责"做"，记忆负责"记"，规划负责"拆解与迭代"。

一、基础核心组件（必备）

1. 大模型大脑（LLM / 多模态模型）

Agent 的推理核心，负责理解任务、思考规划、生成决策、调用工具、总结结果。

  • 能力：自然语言理解、逻辑推理、反思、生成函数调用参数
  • 可选：多模态模型（看图、音视频）

2. 记忆系统（Memory）

保存信息，区分短期 / 长期记忆，解决 LLM 上下文窗口有限的问题。

类型 存储位置 说明
短期记忆（上下文记忆） Prompt 对话历史、本轮任务中间步骤
长期记忆 向量库 持久化知识、过往经验，通过检索召回（RAG）
实体记忆 结构化存储 人物、参数、业务实体等结构化信息

3. 规划器（Planner）

把一个复杂目标拆解成多个子任务，制定执行步骤。

  • 简单：链式思考 CoT
  • 复杂：Plan-and-Solve、ReAct、Tree of Thoughts
  • 支持动态重规划：发现子任务失败时自动调整

常见范式： - ReAct：推理（Reason）+ 行动（Act）交替循环 - Plan-and-Execute：先整体规划再逐步执行 - Reflexion：引入反思机制，根据结果迭代优化

4. 工具调用模块（Tool / Action Executor）

Agent 对外操作的手脚，让模型可以与外部世界交互。

  • 工具类型：代码解释器、API 调用、数据库查询、浏览器搜索、文件读写等
  • 接入协议：Function Calling、MCP（Model Context Protocol）
  • 执行器职责：解析模型输出的工具调用指令、参数校验、执行、捕获返回结果 / 异常

5. 反思与校验（Reflection / Critic）

Agent 做完一步之后自我检查：结果是否正确、有没有遗漏、是否偏离目标，用来修正错误。

  • 单步反思：每一步执行完立即校验
  • 任务复盘反思：任务结束后整体评估

二、扩展组件（中大型 Agent 常用）

组件 说明
检索器（Retriever / RAG） 从知识库检索外部资料，给 Agent 提供事实依据，减少幻觉
状态管理（State） 保存 Agent 任务状态、子任务进度，支持断点续跑
感知 / 输入（Perception） 接收用户指令、文本、图片、音频、工具返回结果、环境状态等
编排与控制循环（Orchestration） 驱动"感知 → 思考 → 行动 → 观察"循环，管理工具调用时机、终止条件、错误重试
护栏与安全（Guardrails） 输入输出校验、权限控制、Human-in-the-loop、成本与步数限制

三、多 Agent 系统

当多个 Agent 协作时，还需要额外的角色分工与通信协作机制：

  • Orchestrator：主控 Agent，负责任务分发与结果汇总
  • Worker Agent：执行具体子任务的专项 Agent
  • 通信协议：消息队列、共享状态、事件总线等

代表框架：LangGraph、AutoGen、CrewAI。
