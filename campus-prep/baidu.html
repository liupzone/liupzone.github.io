很多人现在提到百度，第一反应还是搜索。

后端 / 搜索推荐方向

百度后端和很多 Java 导向的大厂不太一样。

搜索推荐、基础系统这类方向，对 C++ 的偏好会更明显。

面试里容易拉开差距的地方，主要有 4 个：

  1. C++ 深度：内存管理、STL、智能指针、多线程
  2. 基础算法稳定性：树、链表、数组、二分这些不能掉链子
  3. 系统基础：OS、网络、数据库这些要能往深里答
  4. 工程感：不是只会写题，还得能讲清楚为什么这么设计

简单说，百度后端不太吃“我会一点框架”的路子，更看重底层基本功。

AI / 大模型方向

如果你投的是文心、AI 搜索、飞桨、昆仑芯这些方向，面试官通常不会满足于“会调模型”。

他们更想看你有没有工程化能力：

  1. 训练框架熟不熟：Paddle / PyTorch / TensorFlow
  2. 微调方法会不会：LoRA、Prompt Tuning 等
  3. 部署优化懂不懂：TensorRT、ONNX、量化、剪枝
  4. 原理能不能讲明白：Transformer、注意力机制、位置编码

一句话概括：百度 AI 岗不是只看你会不会训模型，更看你能不能把模型真正跑起来。

自动驾驶方向

百度自动驾驶相关岗位的关键词很明确：

  • C++ 基础
  • 感知 / 多模态基础模型
  • 点云和 3D 检测
  • ROS、线代、概率论、卡尔曼滤波

如果你有自动驾驶、机器人、感知、SLAM 相关项目经验，哪怕项目不算特别大，也比空讲“我对自动驾驶很感兴趣”更有说服力。

毕竟兴趣谁都能写，项目细节才会出卖你。这个“出卖”是中性词。有货的人会在这里特别占便宜。

LeetCode 高频题 Top 20（真实面经数据）

先说结论：百度的算法题整体不算最卷，但非常看基本功。

尤其是后端方向，树题频率明显高于很多公司。很多人把主要精力都砸在链表和 DP 上，结果到了百度，被一棵树教育了一整轮。多少有点冤。

🔴 第一梯队：必刷

1. 二叉树的层序遍历（No.102）⭐⭐⭐⭐⭐

  • 考察频次：后端 5 次
  • 核心思路：BFS + 队列，逐层处理节点
  • 必刷变形：锯齿形层序、右视图、层平均值、最大宽度
  • 备考提示：别只会背模板，要能把“为什么按层处理”讲清楚

2. 反转链表（No.206）⭐⭐⭐⭐⭐

  • 考察频次：后端 4 次
  • 核心思路：三指针迭代 / 递归
  • 常见追问：环形链表 II、相交链表、K 个一组翻转
  • 备考提示：这题看起来基础，但一旦代码写得磕巴，面试官心里基本有数了

3. 数组中的第 K 个最大元素（No.215）⭐⭐⭐⭐

  • 考察频次：算法岗 7 次
  • 核心思路：快速选择 / 小顶堆
  • 备考提示：这是百度算法岗最值得优先拿下的一道题，最好两种解法都能讲

4. 寻找两个正序数组的中位数（No.4）⭐⭐⭐⭐

  • 考察频次：后端 3 次
  • 核心思路：二分分割
  • 备考提示：这题能写出来，本身就是一个很明显的加分项

5. LRU 缓存机制（No.146）⭐⭐⭐⭐

  • 考察频次：后端 3 次
  • 核心思路：哈希表 + 双向链表
  • 备考提示：写出来只是起点，最好能继续解释为什么双向链表更合适

百度刷题规律总结：

  1. 树题优先级最高：尤其是层序遍历全家桶
  2. 链表不难，但要稳：反转、环形、相交、倒数第 N 个都得熟
  3. 基础设计题常见：LRU 这种题经常拿来追问实现细节
  4. 算法岗单独注意 215：第 K 大元素是明显高频题
  5. Hard 题不是主旋律：百度更常见的杀伤方式，是用基础题把你追问穿

技术面试考点：代码写完，还会追这些

C++ 专项（后端 / 搜索 / 自动驾驶方向）

考点 高频问题
内存管理 new/delete 和 malloc/free 区别？内存泄漏怎么查？
智能指针 shared_ptr 引用计数原理？weak_ptr 为什么能解循环引用？
多线程 mutex、condition_variable、线程同步怎么用？
STL vector 扩容、map 和 unordered_map 区别？
性能优化 内存对齐、缓存友好、减少拷贝

C++ 在百度面试里经常不是“考你会不会”，而是“考你到底懂多少”。

你说自己会智能指针，面试官可能接着问引用计数、循环引用、线程安全。你说自己熟悉 vector，后面就可能追问扩容、迭代器失效、内存连续性。问题不花哨，但很能区分深浅。

百度面试风格：基础扎实 + AI 视野

百度面试有三个很明显的特点。

1. 题目不一定最难，但追问很讲基本功

百度不是那种上来就给你两道 Hard 的公司。

但它很喜欢用基础题看你到底熟不熟。比如一道层序遍历，你写完了，面试官可能立刻接锯齿形、右视图、层最大值。你如果只是“会做原题”，会很快露馅。

2. C++ 深度是拉开差距的地方

尤其是搜索推荐、系统、自动驾驶这些方向。

同样一道题，能写出来是及格；能顺手解释内存、拷贝、复杂度、线程安全，就是另一档了。

3. AI 视野是加分项

哪怕你投的不是纯算法岗，如果你能把大模型、训练推理、工程化落地讲得比较明白，通常都会比只会背八股更占便宜。

简单说：百度想要的，不是只会做题的人，而是基础稳、工程感强、对 AI 方向也不陌生的人。

高概率出现的追问组合

这些组合很值得提前练：

  • 层序遍历 → 锯齿形层序 → 右视图
  • 反转链表 → 环形链表 II → 相交链表
  • LRU → 线程安全版本怎么改
  • 第 K 大元素 → 快速选择和堆怎么权衡
  • Transformer → LoRA → 推理部署优化

百度笔试特点

从公开面经整理来看，百度笔试通常有几个特点：

  • 时间不算短：整体比较吃专注度
  • 基础覆盖面大：算法、OS、网络、数据库都有可能出现
  • 编程题偏基础到中档：不是全靠 Hard 题压人
  • AI 岗会单独加码：会更看模型原理和工程理解

它不一定是最折磨人的笔试，但很容易让你产生一种错觉：题目好像都见过，做完才发现细节丢了不少分。

备考计划

阶段 准备重点
树题专项 层序遍历全变形、中序、右视图、LCA、构造二叉树
链表专项 反转、环形、相交、倒数第 N 个、K 组翻转
C++ / 语言深度 智能指针、多线程、STL、内存管理
难题突破 中位数、LRU、第 K 大元素、摩尔投票
AI / 自动驾驶加分项 Transformer、LoRA、部署优化、感知基础

最低备考标准：

  • [ ] 层序遍历和 3 个变形题能快速写出
  • [ ] 环形链表 II 的推导能讲清楚
  • [ ] LRU 能手写，不靠模板
  • [ ] 中位数题知道正确解法，不只是暴力合并
  • [ ] 至少有一个项目能讲出真实技术难点

如果你的目标是百度后端，这份计划里最不能省的，是前期。

树、链表、C++ 深度这三块没打牢，后面的 AI 视野和项目包装，很难真正把你抬起来。

如果你的目标是百度 AI 岗，那就再加一句：

别只刷题。

刷题是门票，模型训练、推理、部署这些工程能力，才更像决定你能走多远的东西。

最后说一句。

百度这家公司，最容易让人误判的地方，是看起来没有那么“张牙舞爪”。

但真到面试桌上，你会发现它特别吃基础，特别看深度。

树题不熟，容易被打穿。

C++ 不扎实，容易被追穿。

AI 方向只懂名词，不懂工程化，也很难真正拿分。

所以准备百度，别想着走捷径。

把基础做厚，再补上 AI 视野，这条路线最稳。

祝你百度面试顺利，拿到满意的 Offer。🎯
