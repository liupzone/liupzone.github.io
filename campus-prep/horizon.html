一、公司画像 & 校招节奏

地平线（Horizon Robotics）成立于，总部北京，由余凯创立——他此前是百度主任科学家，深度学习领域的顶尖学者之一。这个背景很重要：你能理解为什么地平线的技术基因如此纯正。

核心产品是征程系列芯片（征程5/征程6），这是专为自动驾驶设计的AI处理器，核心是地平线自研的BPU（Brain Processing Unit，脑处理单元）架构。简单类比：英伟达的GPU是通用并行计算，地平线的BPU是专为神经网络推理优化的定制芯片，功耗更低，在车端推理场景更有竞争力。

，地平线在港股上市（股票代码：9660.HK），估值约700亿港元。商业化进展非常扎实：大众汽车投资50亿欧元与地平线成立合资公司CARIZON，比亚迪、理想、长城、奇瑞等超过60家车企都在用地平线的芯片方案。这不是PPT公司，是真实跑量产的。

员工约1万人，技术人员占比超70%。这个比例在中国科技公司里算高的。你进去大概率跟工程师打交道，不用太担心内耗问题——当然也正因为此，技术能力要求非常高。

一个需要提前想清楚的问题：地平线是做芯片的，不是做互联网产品的。这意味着你写的代码最终跑在嵌入式设备上，有实时性要求，有功耗约束，有内存限制。如果你只喜欢做纯后端、纯前端，地平线可能不是最合适的地方。但如果你对AI+硬件的结合感兴趣，地平线是国内最好的舞台之一。

第三梯队：AI专项算法题（地平线特色，必须准备）

这是和其他公司最不一样的地方。地平线算法岗会考以下几类"AI算法题"，本质上是手写实现，而不是刷LeetCode题库。

1. NMS（非极大值抑制）手写实现

这几乎是地平线算法岗的必考题。NMS是目标检测后处理的核心步骤。面试官会让你当场写C++代码：

输入：一组检测框 boxes（每个框有x1,y1,x2,y2坐标和置信度score）
输出：经过NMS筛选后保留的检测框索引列表
参数：iou_threshold（IOU阈值，通常0.5）

伪代码逻辑：
1. 按score降序排列所有框
2. 循环：取score最高的框，加入结果列表
3. 计算该框与剩余所有框的IOU
4. 删除IOU > threshold的框（认为它们与当前框重复）
5. 重复2-4，直到没有框

2. IOU（交并比）计算

IOU = 交集面积 / 并集面积
交集 = max(0, min(x2_a, x2_b) - max(x1_a, x1_b)) * max(0, min(y2_a, y2_b) - max(y1_a, y1_b))
并集 = 面积A + 面积B - 交集

这个公式短，但容易在边界条件上出错（两个框不相交的情况）。

3. Softmax数值稳定实现

普通Softmax在指数运算时会溢出。数值稳定版：先减去最大值再做指数运算。这个考察的是对数值计算细节的理解，而不是背公式。

4. GEMM矩阵乘法实现

最基础的矩阵乘法C++实现，考察内存访问模式和缓存友好性。高阶版本可能要求谈谈如何用SIMD指令（AVX2）加速。

刷题策略总结： 1. 第一梯队5题必须能闭眼写出正确C++代码（不是Python） 2. AI专项4类题（NMS/IOU/Softmax/GEMM）至少各手写一遍，理解逻辑 3. 第二梯队10题争取在面试前都过一遍

四、技术面试考点

深度学习专项（算法岗，权重最高）

卷积神经网络基础： - Conv层输出尺寸计算：output = (input + 2*padding - kernel) / stride + 1，这个公式要能秒答 - Batch Normalization：训练时用batch统计量，推理时用running_mean/running_var——这个区别被问到的频率极高 - Depthwise Separable Conv：MobileNet的核心，参数量和计算量的节省比例

Transformer与Vision Transformer： - Self-Attention的计算公式：Attention(Q,K,V) = softmax(QK^T/√d_k)V - 为什么要除以√d_k：防止点积过大导致softmax梯度消失 - ViT是怎么把图片喂进Transformer的：patch embedding，把图片切成16×16的块

目标检测核心问题： - Anchor-based（YOLO）vs Anchor-free（FCOS/CenterPoint）的本质区别和适用场景 - NMS的作用和局限（遮挡场景下的问题），Soft-NMS如何缓解 - 2D检测和3D检测的主要差异（在自动驾驶中，3D检测才有实际意义）

BEV感知（地平线重点）： - 为什么BEV（Bird's Eye View，鸟瞰图）比前视图更适合自动驾驶： - 坐标系统一，多摄像头的视角可以融合到同一平面 - 距离感更准确，不受近大远小的透视畸变影响 - 更容易与激光雷达的点云数据融合 - BEVFusion如何融合摄像头和激光雷达：图像特征投影到BEV空间，再与点云特征拼接

模型量化（工具链岗/算法岗都考）： - FP32→INT8的量化原理：用scale和zero_point参数将浮点数映射到整数范围 - PTQ（训练后量化）vs QAT（量化感知训练）：PTQ更快，QAT精度损失更小 - 量化引起精度损失的根本原因：信息压缩（32bit→8bit），激活值分布不均匀时损失更大 - 关键问题：如何判断哪层对量化敏感（逐层精度分析）

C++专项（全方向必考）

地平线的C++考察比一般互联网公司严格很多，因为代码最终要跑在资源受限的嵌入式设备上，性能是真实约束。

内存管理： - RAII原则：资源获取即初始化，对象析构时自动释放资源——这是C++和C最大的区别之一 - unique_ptr vs shared_ptr：独占所有权 vs 共享所有权，前者零开销，后者有引用计数 - 对象池：推理框架中避免频繁new/delete的常见手段，面试可能要求手写简单实现

多线程： - std::thread + std::atomic + std::mutex 的基本使用 - 无锁队列（lock-free queue）：用于实时推理流水线的生产者-消费者场景，考察对memory_order的理解 - 死锁的四个必要条件和预防方法

性能优化： - SIMD指令（AVX2）：一条指令处理8个float，向量化加速矩阵运算 - 内存对齐：64字节对齐，提升Cache命中率 - 缓存友好代码：行主序遍历矩阵 vs 列主序遍历的性能差异

模板编程（高级加分项）： - 类型推导（auto、decltype） - 函数模板和类模板的基本使用

芯片/系统软件专项（对应方向必考）

计算机组成原理： - Cache一致性（MESI协议）：多核处理器的缓存同步机制，芯片设计必须理解 - DRAM带宽计算：内存带宽 = 数据总线宽度 × 工作频率，是BPU性能的关键约束

Linux内核/驱动（BSP方向）： - 字符设备驱动的注册流程：alloc_chrdev_region → cdev_init → cdev_add - DMA传输：绕过CPU，让外设直接访问内存，减少CPU占用 - 中断处理：上半部（IRQ handler）和下半部（tasklet/work queue）的分工

RTOS与Autosar（系统软件方向）： - 实时操作系统的核心：任务调度（优先级调度/时间片调度），响应时间可预测 - 优先级反转问题和解决方法（优先级继承协议） - 经典Autosar分层架构：应用层 → RTE → BSW → MCAL

五、面经规律总结

面试风格：AI技术深度 + C++工程能力双轨制

地平线的技术面试有一个非常明显的规律：每个技术问题都有两层。

第一层是"知道不知道"——你了解这个技术概念吗？ 第二层是"能不能用"——你能用C++手写出来吗？

停在第一层是不够的。说得出BN层推理时用running_mean，但写不出代码，在地平线的面试里算没过。

五个高概率追问链

链条1：目标检测追问链 "介绍一下YOLO的检测原理" → 追问："NMS是怎么实现的？手写一下" → 追问："遮挡场景下NMS有什么问题？Soft-NMS怎么解决？"

链条2：模型量化追问链 "介绍一下INT8量化" → 追问："scale和zero_point是怎么计算的？" → 追问："QAT训练流程和普通训练有什么区别？"

链条3：C++多线程追问链 "如何用mutex保证线程安全" → 追问："无锁队列怎么实现？" → 追问："std::atomic的memory_order参数有什么用？"

链条4：BEV感知追问链 "BEV感知和前视图感知有什么区别" → 追问："BEVFusion是如何融合摄像头和激光雷达的？" → 追问："BEV特征图的分辨率和感知范围如何权衡？"

链条5：模型部署追问链 "PyTorch模型怎么部署到嵌入式设备上" → 追问："ONNX导出有什么注意事项？" → 追问："算子融合是怎么做的？能举个例子吗？"

加分项：体现行业热情

地平线的面试官非常喜欢有"自动驾驶热情"的候选人，不只是把这当成一份工作。以下几个表现会明显加分：

  • 了解地平线BPU：面试前查清楚征程5/征程6的基本规格（128 TOPS / INT8算力），能主动聊BPU的设计思路
  • 了解行业进展：BEVFusion、Transformer在自动驾驶中的应用，L2++和L3的技术差异
  • 有端到端部署经验：哪怕是课程项目，能讲清楚"我把这个模型从PyTorch训练到部署到树莓派/Jetson上"的全流程

笔试特点

  • 题型：C++/Python编程题2-3道 + AI基础选择题 + 数学题（矩阵运算/概率统计）
  • 时间：90-
  • 编程题难度：以Medium为主，C++实现，注意代码质量
  • AI基础题：卷积输出尺寸计算、量化基础、BN层行为，不是很难但需要真正掌握
  • 数学题：矩阵乘法的时间复杂度、贝叶斯公式的简单应用

需要避开的误区

误区1：只准备LeetCode AI算法题（NMS/IOU手写）不准备，是很多同学面地平线翻车的直接原因。

误区2：只会Python 地平线面试要求C++手写代码，Python伪代码不被接受。算法工程师也不例外。

误区3：只懂理论不会部署 能讲BEV感知原理，但不知道模型怎么量化、怎么导出ONNX，在地平线面试里是减分项。

误区4：忽视自动驾驶业务背景 地平线不是通用AI公司，面试官想要的是对自动驾驶真正感兴趣的人。提前了解行业背景，能让面试体验好很多。
