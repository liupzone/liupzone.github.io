一、公司画像 & 校招节奏

华为做智能驾驶，有一点很不一样：华为不造整车。

这句话值得反复理解。华为的定位是智能驾驶供应商，类似博世在传统汽车里的角色，但技术层级要高得多。具体产品是乾坤ADS（高阶智能驾驶系统），已经搭载在问界M5、M7、M9，阿维塔11，以及智界S7等多款量产车型上。

这意味着你写的代码，会在真实路上高速行驶的车里运行。不是Demo，不是内部测试，是真车。这个压力和普通互联网产品的开发体验完全不同。

华为智能驾驶解决方案（原名智能汽车解决方案BU，底独立化运营趋势明显）的技术特点可以用四个字概括：全栈自研。

从底层芯片（MDC计算平台，搭载华为昇腾芯片系列）到操作系统（HarmonyOS for Auto），再到感知、规划、控制算法，华为都自己做。这和大部分传统Tier1（采用Mobileye芯片+博世控制器拼接方案）完全不同，也和蔚小理这些车企"买算法、买芯片、自己集成"的路线不同。

全栈自研的代价是：对研发人员的技术深度要求极高。华为智驾面试，绝不只是问你刷了多少道LeetCode。

一个判断题先想清楚：你适合华为智驾吗？

如果你喜欢纯互联网后端、不想接触硬件约束、对实时性和安全性没有特别兴趣，华为智驾可能让你不适应。但如果你对"软件最终要在物理世界产生影响"这件事有兴趣，或者对自动驾驶行业本身有热情，华为智驾是现阶段技术密度最高的选项之一。

第三梯队：自动驾驶专项算法题（华为智驾特色）

这是和纯互联网公司面试最大的差异。华为智驾面试会考一些"场景化算法题"，考的是算法在自动驾驶中的实际应用。

1. 坐标变换手写

给你一个点在相机坐标系下的位置（x, y, z），让你求它在世界坐标系下的位置。需要手写旋转矩阵相乘的代码。

这考察的是：你是否真正用过这些数学工具，还是只会背公式。面试官会进一步追问：四元数相比欧拉角有什么优势（不存在万向节锁问题）。

2. 卡尔曼滤波状态更新

给定系统方程和观测方程，手写卡尔曼滤波的预测步骤和更新步骤。考察对传感器融合基础的理解，而不是背公式。

预测步骤：
  x_pred = F * x_prev + B * u        // 状态预测
  P_pred = F * P_prev * F^T + Q      // 协方差预测

更新步骤：
  K = P_pred * H^T * (H * P_pred * H^T + R)^(-1)  // 卡尔曼增益
  x = x_pred + K * (z - H * x_pred)  // 状态更新
  P = (I - K * H) * P_pred            // 协方差更新

3. A*路径规划简化实现

给一个10×10的栅格地图（0=可通行，1=障碍），写A*算法找从起点到终点的最短路径。C++实现，注意用priority_queue管理open列表，用欧式距离或曼哈顿距离作为启发函数。

4. IOU（交并比）手写

IOU = 交集面积 / 并集面积
交集宽 = max(0, min(x2_a, x2_b) - max(x1_a, x1_b))
交集高 = max(0, min(y2_a, y2_b) - max(y1_a, y1_b))
交集面积 = 交集宽 * 交集高
并集面积 = 面积A + 面积B - 交集面积

边界条件容易出错：两个框不相交时交集宽/高为0，不能出现负数。

5. NMS（非极大值抑制）手写

目标检测后处理的核心步骤，在感知算法岗几乎是必考题。

输入：检测框列表 boxes（含x1,y1,x2,y2和置信度score）
输出：保留的检测框索引列表

步骤：
1. 按score降序排列
2. 取最高score的框，加入结果
3. 计算它与剩余框的IOU
4. 删除IOU > threshold的框
5. 重复2-4，直到列表为空

刷题策略： 1. 第一梯队5题必须能闭眼写出正确C++代码 2. 自动驾驶专项5类题，各手写一遍，理解物理含义 3. 第二梯队10题过一遍，重点掌握思路和边界条件 4. 所有题目都要想：如果有实时性约束，这个解法有什么问题？

四、技术面试考点

C++深度考点（全方向必考，权重极高）

华为智驾的C++考察比大多数互联网公司严格，原因是代码最终要跑在MDC计算平台上，有实时性约束（规划控制100ms，感知处理有帧率要求），性能不是加分项，是硬性要求。

内存管理：

  • RAII原则：资源获取即初始化，对象析构时自动释放——这是C++区别于C最重要的设计思想之一
  • unique_ptr vs shared_ptr：独占所有权（零开销）vs 共享所有权（有引用计数开销）——在嵌入式场景prefer unique_ptr
  • 对象池：推理流水线中避免频繁new/delete的常用手段，面试可能要求手写简单版本
  • 内存对齐：64字节对齐与Cache行的关系，alignas(64) 的使用

多线程与并发：

  • std::thread + std::mutex + std::condition_variable 的基本组合，生产者-消费者模式
  • std::atomic 和 memory_order：理解 memory_order_relaxed / acquire / release 的语义，不要只会默认参数
  • 无锁队列（lock-free queue）：用于感知→规划的数据传递流水线，理解CAS（Compare-And-Swap）操作
  • 死锁的四个必要条件：互斥、持有并等待、不可剥夺、循环等待，以及预防策略

性能优化：

  • SIMD指令集：ARM NEON（MDC平台的ARM架构）和x86 SSE/AVX，一条指令处理多个float的原理
  • 缓存友好代码：行主序遍历矩阵 vs 列主序的Cache miss差异，点云数据的内存布局优化
  • 编译器优化：__builtin_expect 分支预测提示，内联函数（inline），循环展开

实时性：

  • 实时操作系统（RTOS）基础：任务优先级、抢占式调度、时间片轮转
  • 优先级反转：低优先级任务持有高优先级任务需要的锁——优先级继承协议如何解决
  • 确定性执行：为什么实时系统不喜欢动态内存分配（new/delete的时间不可预测）

感知算法考点

深度学习基础：

  • 卷积输出尺寸公式：output = (input + 2*padding - kernel) / stride + 1——必须能秒算
  • BatchNorm的训练/推理差异：训练时用当前batch的均值方差，推理时用running_mean/running_var——被问到的概率极高
  • Depthwise Separable Convolution：MobileNet的核心，参数量和计算量各减少多少倍

目标检测：

  • Anchor-based（YOLOv5）vs Anchor-free（FCOS/CenterPoint）的本质区别
  • NMS的局限性：遮挡场景下为什么会误删真实框，Soft-NMS和DIoU-NMS如何缓解
  • 2D检测和3D检测的主要差异，为什么自动驾驶必须做3D检测

BEV感知（重点）：

BEV（Bird's Eye View，鸟瞰图）是华为乾坤ADS的核心感知框架，面试必考。

  • 为什么BEV比前视图更适合自动驾驶：
  • 坐标系统一，多摄像头视角融合到同一平面，消除了视角差异
  • 距离感更准确，不受近大远小的透视畸变影响
  • 更容易与激光雷达点云数据融合（都在同一个BEV坐标系）
  • BEVFusion：图像特征通过LSS（Lift-Splat-Shoot）方式投影到BEV空间，再与点云的BEV特征拼接融合
  • BEVDet：纯相机BEV感知方案，避免依赖激光雷达，成本更低但精度有取舍

激光雷达处理：

  • 点云的挑战：稀疏性（远处点少近处点密）、无序性（没有像像素那样的grid结构）
  • PointNet：每个点独立处理+全局池化，解决无序性
  • VoxelNet：体素化（把点云划分到小格子里），解决稀疏性
  • PointPillar：体素化在垂直方向做全局池化（"柱"），实时性更好，量产场景更常用

规划控制考点

路径规划：

  • A*算法：f(n) = g(n) + h(n)，启发函数h的选择影响搜索效率和最优性
  • Hybrid A：将车辆运动学约束（最小转弯半径）引入A，生成实际可行驶路径
  • RRT（快速随机树）：随机采样，适合高维空间，但路径质量不如A*

轨迹规划：

  • 为什么需要轨迹平滑：路径规划的结果是折线，直接执行会导致急剧转向，不舒适也不安全
  • 贝塞尔曲线：控制点决定曲线形状，3次贝塞尔4个控制点，曲线过起终点
  • 三次样条插值：过所有路径点，曲率连续，更适合精确轨迹跟踪

控制算法：

  • PID控制：比例（当前误差）、积分（历史误差累积，消除稳态误差）、微分（误差变化率，抑制超调），横向控制最常用
  • MPC（模型预测控制）：在未来N步内预测车辆状态，求解最优控制序列，只执行第一步，然后滚动优化——比PID能提前应对曲率变化

嵌入式/系统考点

Autosar架构：

  • Classic Autosar：三层结构——应用层（SWC）→ RTE（运行时环境）→ BSW（基础软件）→ MCAL（微控制器抽象层）
  • RTE的作用：隔离应用层和底层，应用层不直接访问硬件，通过RTE调用BSW服务
  • Adaptive Autosar：基于POSIX，服务化架构（Service-Oriented Architecture），适合高算力平台（如MDC）

Linux驱动：

  • 字符设备驱动流程：alloc_chrdev_region → cdev_init → cdev_add → device_create
  • DMA（直接内存访问）：让外设（如激光雷达控制器）直接访问主存，不占用CPU
  • 中断处理：上半部（IRQ handler，快速响应）和下半部（tasklet/work queue，延迟处理耗时操作）

通信协议：

  • CAN总线：差分信号，多主总线，帧结构（标准帧/扩展帧），错误检测机制（CRC/ACK/位填充）
  • 车载以太网（TSN）：时间敏感网络，通过时间同步和流量调度保证确定性延迟，用于摄像头数据传输

五、面经规律总结

面试结构：3-5轮技术面是常态

华为智驾的面试轮次多，但每轮侧重点不同：

  • 第1轮：基础技术面，C++基础+数据结构+1-2道算法题
  • 第2轮：专业方向深度面，感知/规划/嵌入式的专项考察
  • 第3轮：系统设计面，"如果让你设计一个感知模块，你会怎么做"
  • 第4-5轮：综合面+主管面，考察综合能力和团队fit
  • HR面：薪资意向、入职时间

面试时间跨度较长：华为整体流程比互联网公司慢，从一面到拿Offer有时候要2-3个月。这期间要保持其他公司的面试进行，不要把鸡蛋放在一个篮子里。

五个高概率追问链

链条1：C++内存管理追问链 "介绍一下智能指针" → 追问："unique_ptr和shared_ptr的实现原理有什么区别？" → 追问："shared_ptr在多线程场景下是否安全？引用计数的修改是原子操作吗？" → 追问："在嵌入式/实时系统中，你会如何避免频繁内存分配？"

链条2：BEV感知追问链 "介绍一下BEV感知" → 追问："LSS（Lift-Splat-Shoot）如何把2D图像特征投影到3D空间？" → 追问："BEVFusion和纯相机方案的权衡点是什么？" → 追问："BEV特征图的分辨率和感知范围如何权衡？"

链条3：路径规划追问链 "说说A算法" → 追问："Hybrid A和普通A的区别？为什么需要引入车辆运动学？" → 追问："如果A找到的路径有急剧转向，你怎么处理？" → 追问："实时系统中A*的时间复杂度是否可接受，有什么优化方案？"

链条4：多线程追问链 "如何保证线程安全" → 追问："无锁队列是怎么实现的？" → 追问："std::atomic的memory_order有哪些，memory_order_relaxed和memory_order_acquire有什么区别？" → 追问："在感知→规划的数据传递中，你会选择有锁还是无锁方案，为什么？"

链条5：卡尔曼滤波追问链 "介绍一下卡尔曼滤波" → 追问："EKF（扩展卡尔曼滤波）和标准KF有什么区别，为什么需要线性化？" → 追问："卡尔曼增益K的物理含义是什么？K接近0和接近1分别意味着什么？" → 追问："UKF（无迹卡尔曼滤波）是为了解决什么问题？"

笔试特点

华为笔试通常分两部分：

通用编程题（2-3道）： - 难度Medium为主，偶有Hard - 必须用C++，评测时会检查代码质量 - 注意边界条件，华为笔试评测比较严格

智驾专项题（选择/简答）： - 自动驾驶算法基础（感知/规划/控制各方向有涉及） - C++基础知识（内存管理、多线程、虚函数等） - 嵌入式/实时系统概念（RTOS、CAN总线等）

数学题：矩阵运算、概率统计基础，难度不高但需要真正掌握。

加分项：体现行业热情

华为智驾的面试官希望看到你对这个行业真正感兴趣，而不只是把华为当成找工作的一个选项。

以下表现会明显加分： - 了解乾坤ADS的基本情况（已搭载车型、与特斯拉FSD的主要差异） - 了解MDC平台（昇腾芯片系列、算力规格），能主动提及 - 有端到端的自动驾驶项目经验（哪怕是课程项目），能讲清楚感知→规划→控制的完整链路 - 关注行业最新进展（端到端自动驾驶、世界模型在自动驾驶中的应用）

需要避开的误区

误区1：把华为智驾当普通互联网公司准备 只刷LeetCode，不准备自动驾驶算法知识，是最常见的翻车原因。

误区2：忽视C++深度 会Python不够，华为智驾要求C++手写代码，而且会追问到内存模型和性能优化层面。

误区3：不了解自动驾驶基础概念 感知/规划/控制是三个独立体系，投哪个方向就要深入了解哪个方向，不能三个都浮皮潦草。

误区4：只准备算法，忽视系统设计 华为智驾的高轮次面试（第3-4轮）会考系统设计，比如"如何设计一个融合感知系统的架构"，需要有全局视野。

校招节奏

总体原则

华为智驾的备考重心和普通互联网公司有明显不同：自动驾驶专项知识（感知/规划/控制任选一个深入）和C++性能优化，合计占备考时间的60%以上。LeetCode是必要的，但不是核心竞争力。

每阶段详细任务

：C++深度专项 - 智能指针：unique_ptr实现原理（移动语义+析构器），shared_ptr的引用计数（原子操作），手写简单的shared_ptr - 多线程：生产者-消费者（mutex+condition_variable），无锁队列（CAS+atomic） - RAII：理解"资源获取即初始化"，对象析构保证资源释放，避免内存泄漏 - 性能优化：内存对齐（alignas），缓存友好代码（行主序遍历），了解SIMD概念 - 验收标准：能手写线程安全队列，能解释shared_ptr引用计数在多线程下的正确性

：算法专项 - 第一梯队5题：反转链表/层序遍历/快速排序/最大子数组和/LRU，C++各写3遍 - 拓扑排序：BFS版本（Kahn算法），DFS版本，应用：任务依赖调度 - 图论基础：Dijkstra（最短路径，路径规划场景），BFS/DFS - 自动驾驶专项：IOU手写、NMS手写、A*简化版、坐标变换 - 验收标准：NMS完整C++代码能在内写完且逻辑正确

：感知算法 - 深度学习基础：CNN/Transformer/卷积输出尺寸/BN层推理行为 - 目标检测：YOLO基本原理（网格划分/Anchor/置信度），NMS的作用和局限 - BEV感知：为什么需要BEV，LSS投影基本原理，BEVFusion的融合策略 - 点云处理：为什么点云难处理（稀疏+无序），PointPillar的体素化思路 - 验收标准：能解释"为什么BEV比前视图更适合自动驾驶"的3个理由，能手写NMS

：规划控制 - 路径规划：A算法（手撕简化版），Hybrid A的运动学约束，RRT了解即可 - 轨迹规划：贝塞尔曲线（控制点和曲线的关系），三次样条插值基本概念 - 控制算法：PID的物理含义（P响应当前，I消除稳态误差，D抑制超调），MPC的滚动优化思想 - 卡尔曼滤波：预测步骤+更新步骤，EKF的线性化思路，卡尔曼增益的物理意义 - 坐标变换：旋转矩阵/四元数/欧拉角的相互转换，手写3D坐标变换代码 - 验收标准：能手写卡尔曼滤波的预测和更新步骤，能解释MPC和PID的核心区别

：系统知识 - Autosar：Classic Autosar三层架构（SWC/RTE/BSW/MCAL），Adaptive Autosar的服务化思想 - RTOS：任务调度（优先级抢占/时间片），优先级反转的成因和解决方案（优先级继承） - Linux驱动：字符设备驱动的注册流程，DMA和中断处理的基本概念 - CAN总线：帧结构（标准帧11位ID/扩展帧29位ID），差分信号的抗干扰原理 - MDC平台：了解昇腾310/910芯片的基本情况，NPU和CPU/GPU的计算范式区别 - 验收标准：能画出Autosar的分层架构图，能解释RTOS中优先级反转问题

：冲刺收尾 - 了解华为乾坤ADS：搭载车型（问界M5/M7/M9/阿维塔/智界），与特斯拉FSD的主要技术路线差异 - 整理项目经历：把自己的项目整理成"感知→规划→控制"或"算法→工程→优化"的完整链路来描述 - 系统设计练习：对着镜子讲"如何设计一个前融合感知系统"，能说清楚数据流和模块边界 - 面经复盘：把5个追问链各讲一遍，检查是否能回答到底层

最低备考标准（入场门槛）

  • [ ] C++ RAII：能解释RAII，能手写unique_ptr的简化实现
  • [ ] 无锁数据结构：理解CAS操作，能描述无锁队列的实现思路
  • [ ] NMS手写：能在纸上写出正确的C++代码，逻辑完整，边界条件正确
  • [ ] BEV感知：能说出BEV比前视图更适合自动驾驶的2-3个理由
  • [ ] MPC基础：能解释MPC和PID的核心区别，为什么MPC在自动驾驶中更常用
  • [ ] 华为背景：了解乾坤ADS的基本情况和华为智驾的全栈自研定位

达不到以上6条标准，面试华为智驾的胜算很低。这不是吓人，是实话。
